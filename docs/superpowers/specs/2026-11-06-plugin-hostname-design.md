# TrafficMonitor 主机名插件 设计文档（2026-11-06）

## 意图与原因

在 TrafficMonitor 浮动窗口最上面一行显示自定义主机名。主机名内容来自程序运行目录下的
`插件-主机名.txt`，便于为不同机器分发统一的 TrafficMonitor 配置（同一 ini，不同主机名），
而不需要改动程序设置。

## 目标 / 非目标 / 反目标

- **目标**：新插件 `PluginHostName.dll`；读取 exe 所在目录的 `插件-主机名.txt`；
  在浮动窗口显示"主机名：\<内容\>"；文件修改后无需重启即生效。
- **非目标**：不做插件设置界面（文件名固定）；不改主程序代码；不控制任务栏窗口布局
  （任务栏同样会显示该插件项，顺序仍由主程序设置决定）。
- **反目标**：为达到"最上面一行"而修改主程序排序逻辑（应由用户在显示设置中调整一次）。

## 约束

- 插件接口 `PluginInterface.h`（API version 8），不得重写 `GetAPIVersion()`
- 项目加入现有 `TrafficMonitor.sln`；工具集 v143、Unicode；**不使用 MFC**（纯 Win32）
- 源文件保存为 UTF-8 with BOM（与仓库现有源文件一致）
- `GetItemId()` 仅字母数字，全局唯一
- 辅助脚本用 Go 或 C++，不用 Python（用户全局偏好）

## 方案比较（已由用户选定方案 A）

- **方案 A（选定）**：标准文本显示项 `IPluginItem`（标签"主机名" + 值=文件内容）。
  简单，自动适配皮肤/颜色/DPI；"排到最上面"由用户在主程序
  "显示设置 → 设置显示项目顺序"中上移一次即可。
- **方案 B（否决）**：自绘项 `IsCustomDraw()+DrawItem()`。仅当需要特殊样式才有意义，
  增加自绘/暗色模式适配成本，本需求不需要。
- **方案 C（否决）**：修改主程序强制把插件项排在首位。影响所有用户/所有插件，超出插件范围。

## 行为定义

1. **文件路径**：`<TrafficMonitor.exe 所在目录>\插件-主机名.txt`（用 `GetModuleFileNameW(nullptr)` 定位，
   不是插件 dll 所在的 plugins 子目录）。
2. **读取时机**：`OnInitialize()` 首次加载时读取一次；`DataRequired()`（约每秒一次）中
   通过 `GetFileAttributesEx` 比较文件最后写入时间与大小，变化才重读。
3. **解析规则**：
   - 编码自动识别：UTF-8（BOM 可有可无）→ UTF-16LE（BOM）→ 回退 ANSI（`CP_ACP`，GBK）
   - 取**第一行**，修剪首尾空白；解析结果为空视为读取失败
4. **后备**：文件不存在或内容为空 → 显示系统主机名（`GetComputerNameW`）。
5. **显示**：标签"主机名"，值为解析出的主机名；示例文本 `MY-COMPUTER-NAME`
   （用于宽度计算，取足够长的保守值）。
6. **文件不存在不是错误**：静默后备，不弹窗、不写日志。

## 留给实现者的决定

- 内部文件组织（建议：核心解析函数独立成对，便于用独立测试程序验证）
- `ItemId` 具体取值（仅字母数字即可）

## 验收

- Release|x64 与 Release|x86 编译通过，dll 落在 `Bin\...\plugins\`
- 独立测试程序覆盖：UTF-8 BOM / UTF-8 无 BOM / GBK / UTF-16LE / 空 / 纯空白 / 多行 / 首尾空白
- 主程序加载插件后浮动窗口显示"主机名：…"，改文件后约 1 秒内刷新
